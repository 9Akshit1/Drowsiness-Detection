Summary:
This project implements a robust, real-time driver drowsiness monitoring system optimized for edge computing environments. 
By integrating computer vision with adaptive signal processing, the system tracks key behavioral indicators—specifically 
Eye Aspect Ratio (EAR), Mouth Aspect Ratio (MAR), blink frequency, and Percent of Eye Closure (PERCLOS)—alongside dynamic head-pose motion metrics, 
such as angular velocity of pitch and tilt. To ensure environmental robustness, the system features a dynamic calibration 
phase that establishes personalized baseline thresholds for each driver, mitigating variations in facial structure and lighting. 
To move beyond static rule-based alerts, the system utilizes a lightweight ensemble learning classifier trained on a multi-feature
dataset. This classifier evaluates a continuous vector of temporal behavioral data, enabling higher-fidelity detection of early-
stage fatigue compared to conventional threshold-gating methods.

NTHU Dataset Structure (https://link.springer.com/chapter/10.1007/978-3-319-54526-4_9):
There are 36 subjects numbered like 010 or 021, etc...
Alert videos
- normal driving
- talking
- laughing
- looking left/right
Drowsy videos
- yawning
- slow blinking (high PERCLOS)
- falling asleep
- repeated nodding
- combinations of these behaviors
The original recordings are about 1–1.5 minutes for each behavior, and they also provide longer 2–10 minute mixed videos that contain transitions between alert and drowsy states.
Therefore, the 1-1.5 minute videos of justo ne single pure behaivor, makes them easy for labeling as either "Alert" or "Drowsy". 
But for the mixed videos, these contain transitions meaning you cannot simply label every window as "drowsy." So, we'll probably ignore these videos or will ahve to later manually determine which portions correspond to alert versus drowsy behavior.

UTA-RLLD Dataset Structure:

Data Folder: UTA-RLLD

DATASET PLAN (dataset_builder.py):
Step 1 — Extract Facial Landmarks
For every frame:
- Detect the face.
- Estimate the facial landmarks (MediaPipe Face Mesh).
- Estimate head pose (pitch, yaw, roll).
- Normalize the landmarks to a frontal reference pose (remove camera orientation as much as possible). 
- Store the raw and normalized landmarks into a dataset (this is the RAW DATASET). 

Subject Calibration (performed once per subject)
For each subject, use the Alert (0.mp4) recording to establish a personalized physiological baseline.
Using the first 5–10 seconds of the Alert video:
Extract facial landmarks.
Compute the frame-level features.
Calculate the mean values of:
- EAR
- MAR
- Head pitch
- Head yaw
- Head roll
Store these values as the subject-specific baseline:
- EAR_baseline
- MAR_baseline
- Pitch_baseline
- Yaw_baseline
- Roll_baseline
Save these baseline values as metadata associated with the subject. These baselines are then used to normalize the features extracted from all three videos (Alert, Low Vigilant, and Drowsy) belonging to that subject.
Then for the actual dataset construction in the steps below for the other videos (0.mp4, 5.mp4, 10.mp4), normalize the frame-level physiological features of every video, including the Alert video itself, using the subject-specific baseline values.

Step 2 — Compute Frame-Level Features
For every video:
Now convert the landmarks into meaningful measurements.
For every frame calculate:
- EAR (Eye Aspect Ratio)
- MAR (Mouth Aspect Ration)
- Head pitch
- Head yaw
- Head roll
- Head pitch velocity = (pitch_i - pitch_(i-1))/Δt   (i = current frame)
- Head yaw velocity = (yaw_i - yaw_(i-1))/Δt         (i = current frame)
- Head roll velocity = (roll_i - roll_(i-1))/Δt      (i = current frame)
Store this into a dataset (this is the FRAME-LEVEL DATASET).

Step 3 — Create Sliding Windows and compute temporal data
Now divide the video into overlapping windows.
For example:
- Window length = 5 seconds
- Stride = 1 second
Each window contains 150 frames (assuming 30 fps).
If a video is 2 min long, then you would have 116 windows.
Instead of feeding all 150 frames into the classifier, summarize the driver's behavior during that window.
- Mean EAR
- Standard deviation
- Minimum EAR
- Maximum EAR
- Blink count
- Blink frequency
- Average blink duration
- Maximum blink duration
- PERCLOS = Closed-eye frames / Total frames
- Mean MAR
- Maximum MAR
- Standard deviation
- Yawn count
- Average yawn duration
- Mean pitch
- Pitch standard deviation
- Maximum pitch velocity
- Average pitch velocity
- Pitch oscillation frequency
- Number of nodding events
- Label
Store this into a dataset (this is the WINDOW DATASET).

MACHINE LEARNING PLAN (model.py):
Step 1 — Split the Dataset
Split the dataset by subject, ensuring that all windows from a given subject belong exclusively to either the training or testing set. This prevents data leakage and evaluates the model's ability to generalize to unseen drivers.
Use the predefined 5-fold subject split provided by the UTA-RLDD dataset (12 subjects per fold). Train on four folds and evaluate on the remaining fold, repeating this process for all five folds and averaging the results.
Now you're testing whether your model generalizes to new people, which is the real deployment scenario.

Step 2 — Normalize Features
Different features have different units.
A model trains better if these are standardized (use the standardizaiton formula, meaning you need to compute the feature means and standard deviations using only the training set. Apply the same transformation to both the training and testing sets.).

Step 3 — Train Several Models
Train several lightweight classifiers and compare them.
Model	Why
Logistic Regression	Simple baseline
Decision Tree	Interpretable
Random Forest	Usually performs very well
XGBoost / LightGBM	Often best accuracy
Linear SVM	Good baseline
For tree-based models (Decision Tree, Random Forest, XGBoost, LightGBM), extract feature importance scores to identify the behavioral indicators contributing most to the predictions.

Step 4 — Hyperparameter Optimization
Perform Grid Search or Random Search with cross-validation using only the training folds to identify the optimal hyperparameters for each model.

Step 5 — Evaluate on training and testing set
Output Accuracy, Precision, Recall, Macro F1 Score, Confusion Matrix for each model and store the results in some file (json, yaml, etc...).
Average all metrics across the five subject folds.

Step 6 — Save the Best Model
Save best_model.pkl or best_model.onnx. Also save feature_scaler.pkl because you'll need the exact same standardization during deployment.

Step 7 — Real-Time Inference

July 19-24, 2026:
Identified bugs like:
- Noticed that the ML model was giving F1 scores of around 0.44. These are terrible valeusa nd soem of the causes were:
- pitch/yaw/roll velocity uses a circular (wraparound-safe) angle difference, not naive subtraction -- naive subtraction spiked to ~43,000 deg/s across the +-180 wrap boundary, which is what caused nod-count to trigger every few seconds and pitch-velocity readouts to look wrong in the annotated demo.
- nod counting is based on angular-prominence peak detection on the pitch signal itself (a genuine nod is a distinct, sufficient excursion), corroborated by a velocity check, instead of counting every raw velocity-threshold crossing.
- Each frame isnt encessarily the exact video's label. So, we shjould discard the first few minutes of the video.
- The 3D normalization was failing to work properly causing upside down views or flickerign views.
- The counts and rates explode or increase even when there was only one event. Like if it was one long held yawn or blink, the coutn and rates would icnrease even though its technically only one event.
